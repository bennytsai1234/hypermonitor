# Hypermonitor Validation 工作流程

## 目的

- 當用戶要求檢查、驗證、審查、重現或評估風險而不安即時改變程式碼時使用此工作流程。
- 除非用戶明確要求修復或實作，否則不要編輯程式碼。
- 不要為了普通的驗證而再次執行 Codebase Atlas；使用此工作流程並將任何過時的 atlas 文件報告為發現。

## 工作流程

1. 保留驗證問題、預期行為或要檢查的風險。
2. 開啟 `docs/hypermonitor_index.md` 並選擇受影響的模組或邊界。
3. 閱讀相關模組文件的範圍、依賴、下游影響、主要流程與已知風險。
4. 選擇最小有用的驗證方法：測試、lint、類型檢查、建置、靜態檢查、冒煙檢查、重現步驟或人工審查。
5. 僅執行或檢視所需內容以獲得請求的信心水準。
6. 分別記錄通過、失敗、阻塞、跳過與不确定的結果。
7. 若需要修復，建議下一個工作流程而非静默改變程式碼。
8. 根據此交付政策完成（若有檔案變更）：只提交（完成工作後進行一次專注的 commit）；否則摘要驗證狀態並說明無需 commit。

## 驗證摘要

摘要：

- 驗證目標
- 受影響的模組或邊界
- 執行的檢查
- 結果
- 阻礙或跳過的檢查
- 推薦的下一個步驟

## 交付政策

只提交（完成工作後進行一次專注的 commit）
