# Hypermonitor Bug 工作流程

## 目的

- 使用此工作流程處理明確的 bug、測試失敗、迴歸、崩潰或不稳定行為。
- 不要為了普通的 bug 修復而再次執行 Codebase Atlas；使用此工作流程並在所有權或流程變更時更新受影響的 atlas 文件。

## 工作流程

1. 開啟 `docs/hypermonitor_index.md` 並選擇最可能擁有問題的模組。
2. 閱讀該模組的依賴、主要流程、已知風險與範圍邊界。
3. 在程式碼中檢視失敗的執行路徑或測試路徑。
4. 判斷缺陷是局限於該模組還是上游輸入導致。
5. 若症狀跨越模組，根據資料、狀態或行為首先出錯的位置選擇主要模組。將其他模組視為邊界模組並保持其變更最小。
6. 將修復集中在擁有模組。邊界變更需要明確的理由。
7. 驗證 bug 已修復並在所有權或流程變更時更新 atlas 文件。
8. 根據此交付政策完成：只提交（完成工作後進行一次專注的 commit）

## 編輯前摘要

當預期需要用戶確認時，摘要並等待（若用戶或專案規則要求在編輯前確認）：

- 症狀
- 根因假設或已確認的根因
- 主要擁有模組與任何邊界模組
- 可能變更的檔案
- 編輯前與編輯後的行為，包括用戶可見的行為與內部職責分割
- 任何跨模組或邊界變更的理由
- 要執行的測試或檢查

## 交付政策

只提交（完成工作後進行一次專注的 commit）
