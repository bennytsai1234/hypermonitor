# Hypermonitor Optimization 工作流程

## 目的

- 使用此工作流程改進現有行為、可靠性、清晰度、可維護性或效能，而不新增不相關的功能。
- 不要為了普通的優化工作而再次執行 Codebase Atlas；使用此工作流程並在結構或所有權變更時更新受影響的 atlas 文件。

## 工作流程

1. 開啟 `docs/hypermonitor_index.md` 並選擇一個目標模組。
2. 閱讀該模組的目前狀態、依賴、主要流程與已知風險。
3. 識別應該變更的最小層次：UI、API、執行期、服務、資料、整合、基礎設施或工具。
4. 列出 2-3 個具體優化方向，然後為此任務選擇一個方向。
5. 除非用戶另有要求，否則保持用戶可見的行為不變。
6. 驗證上游與下游行為仍正常運作。
7. 在結構、所有權或風險變更時更新 atlas 文件。
8. 根據此交付政策完成：只提交（完成工作後進行一次專注的 commit）

## 編輯前摘要

當預期需要用戶確認時，摘要並等待（若用戶或專案規則要求在編輯前確認）：

- 目標模組
- 目前問題
- 候選優化方向與選擇的方向
- 編輯前與編輯後的行為，包括用戶可見的行為與內部職責分割
- 明確的非目標
- 要執行的測試或檢查

## 交付政策

只提交（完成工作後進行一次專注的 commit）
