# Hypermonitor Investigation 工作流程

## 目的

- 當行為、所有權、可行性或根因不明且首要任務是理解系統時使用此工作流程。
- 在調查期間不要編輯程式碼，除非用戶明確要求修復或實作。
- 不要為了普通的調查而再次執行 Codebase Atlas；使用此工作流程並記錄任何需要更新 atlas 的內容。

## 工作流程

1. 保留用戶的原始問題或症狀。
2. 開啟 `docs/hypermonitor_index.md` 並選擇最可能擁有的模組或邊界。
3. 閱讀相關模組文件的範圍、上游依賴、下游影響、主要流程與已知風險。
4. 檢視確認行為所需的實際程式碼、測試、文件、執行路徑、日誌或設定。
5. 分離已確認的事實、假設、未知與假設。
6. 追溯流程直到足夠清楚哪個是擁有者、失敗點或決策邊界，來確定下一個任務。
7. 若需要後續工作，推薦下一個工作流程：bug、功能、優化、重構或驗證。
8. 根據此交付政策完成（若有檔案變更）：只提交（完成工作後進行一次專注的 commit）；否則摘要發現並說明無需 commit。

## 調查摘要

摘要：

- 原始問題或症狀
- 擁有模組或邊界
- 已確認的事實
- 剩餘的未知
- 風險或脆弱假設
- 推薦的下一個步驟

## 交付政策

只提交（完成工作後進行一次專注的 commit）
