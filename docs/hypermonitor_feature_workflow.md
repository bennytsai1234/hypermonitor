# Hypermonitor Feature 工作流程

## 目的

- 使用此工作流程處理目標專案中尚不存在的新行為。
- 不要為了普通的功能開發而再次執行 Codebase Atlas；使用此工作流程並在所有權、API 或流程變更時更新受影響的 atlas 文件。

## 工作流程

1. 保留用戶的原始請求。
2. 開啟 `docs/hypermonitor_index.md` 並找到自然的擁有模組。
3. 閱讀擁有模組文件與任何邊界模組文件。
4. 定義功能邊界：包含的行為、排除的行為、介面、狀態、持久化、外部系統與用戶可見的變更。
5. 若功能跨越模組，根據擁有新行為或狀態生命週期的模組選擇主要模組。將其他模組視為邊界模組並赋予明確的介面職責。
6. 通過擁有模組的既定模式來實現。
7. 驗證新行為並在所有權、API 或流程變更時更新 atlas 文件。
8. 根據此交付政策完成：只提交（完成工作後進行一次專注的 commit）

## 編輯前摘要

當預期需要用戶確認時，摘要並等待（若用戶或專案規則要求在編輯前確認）：

- 原始請求
- 主要擁有模組與邊界模組
- 包含與排除的範圍
- 實作方法
- 編輯前與編輯後的行為，包括用戶可見的行為與內部職責分割
- 要執行的測試或檢查

## 交付政策

只提交（完成工作後進行一次專注的 commit）
