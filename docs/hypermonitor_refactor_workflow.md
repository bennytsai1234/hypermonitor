# Hypermonitor Refactor 工作流程

## 目的

- 當結構、所有權、API 形狀、命名、重複或模組邊界變更而預定行為應該保持不變時使用此工作流程。
- 不要使用重構作為隱藏不相關功能工作或行為變更的手段。
- 不要為了普通的重構而再次執行 Codebase Atlas；使用此工作流程並在所有權、API 或流程變更時更新受影響的 atlas 文件。

## 工作流程

1. 保留用戶的原始請求並確認必須保持不變的行為。
2. 開啟 `docs/hypermonitor_index.md` 並選擇擁有模組與任何邊界模組。
3. 閱讀相關模組文件的範圍、依賴、下游影響、常見變更入口與已知風險。
4. 定義最小的重構邊界與明確的非目標。
5. 若重構跨越模組，根據正在澄清或移動的所有權選擇主要模組。將其他模組視為邊界模組並分別解釋每個邊界調整。
6. 識別保護不變行為的測試、類型檢查、建置檢查或冒煙檢查。
7. 以專注的步驟進行重構，保持公共介面穩定（除非介面變更是明確目標）。
8. 驗證行為與下游整合仍正常運作。
9. 在結構、所有權、API 或流程變更時更新 atlas 文件。
10. 根據此交付政策完成：只提交（完成工作後進行一次專注的 commit）

## 編輯前摘要

當預期需要用戶確認時，摘要並等待（若用戶或專案規則要求在編輯前確認）：

- 原始請求
- 主要擁有模組與邊界模組
- 必須保持不變的行為
- 重構邊界與非目標
- 編輯前與編輯後的行為，包括用戶可見的行為與內部職責分割
- 可能變更的檔案
- 要執行的測試或檢查

## 交付政策

只提交（完成工作後進行一次專注的 commit）
